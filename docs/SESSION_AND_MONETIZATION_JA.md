# Animal Shadow Match — 起動導線・1セット・休憩・広告設計 v3.0

> **v4ゲーム価値追補（2026-10-14）:** 5問セット/続ける・休憩/広告ゼロを維持し、正解の反応と5匹の画面内自由遊びを[ゲーム体験 v4](GAME_VALUE_AND_ENGAGEMENT_JA.md)で詳しく規定。ユーザーの意思を無視した刺激・報酬による引き延ばしは導入しない。


> 更新日: 2026-10-14。**設計のみ・Flutter実装未対応。**
> 本文書は動線・セット長・終了・再開・広告に関して [UI/UX v2](UI_UX_SPEC_JA.md) より優先する。単問画面の寸法・アニメーション等はv2を適用。
> 対象: 文字が読めない2〜5歳。所要時間・試験基準は設計仮説であり、子どもの観察試験で確かめる。

## A. 全体方針（確定）
- **初回も通常もアプリを開くと直接プレイ。** タイトル/ログイン/ステージ一覧/モード選択画面はMVPで作らない。
- **5問を1セット**（約1〜2分の設計仮説）。正答した問題だけカウント。制限時間、残機、ゲームオーバーなし。
- **1〜4問の正答後は自動的に次の問題**。5問目だけ静かな達成画面に切り替える。
- 達成画面では**今解いた5匹の画像を再利用**して並べ、**「さらに5問」「休憩」**の2択を文字なしで表示。勝手に次のセットへ進まない。
- **休憩は静止した1匹と再開ボタン**。Androidホーム/戻るは自然に利用できる。アプリの終了を無理に妨げない。
- **ゲーム中、問題間、達成画面、休憩画面には広告を出さない。** 初期版の広告SDKなし。将来の収益化は保護者用画面で慎重に検討。
- 中断すれば同じ問題・同じ影の配置で復帰。セットの途中で難度を変えない。
- 主目的は「安心して遊びを区切れること」。継続時間を人為的に最大化する仕掛けは使わない。

## B. 誰にとって何がわかりやすいか
### 子ども
開くと動物がいる→影をタップ→色の動物に変わる→新しい動物が出る→5匹集まる→もう少し遊ぶ/おしまいが絵で選べる。文字・音声なしでも完結。
### 保護者
Google Playで何のゲームかを理解→開くとすぐ遊べる→一段落が短い→広告に誤タップする心配がない→いつでも閉じられる。設定・購入・外部サイト等は遊びから分ける。

## C. フロー（実装する画面）
1. BOOT: 初回は新規2択、通常は保存状態確認。いずれもタイトル画面は通らず PLAYへ。
2. PLAY: 動物1匹+下に影2〜4個。文字説明、星、時計、ライフ、バナーなし。押せるのは影カードのみ。
3. WRONG: 同じカードを短く押し込むだけ。同じターゲット・同じ位置で再試行。誤答を責める赤い×、ブザー、減点は禁止。
4. CORRECT question 1〜4: タップ直後に影がカラーの動物に変化、穏やかなバウンス。総時間1.1〜1.5秒（仮説）後に自動で次の動物。二重タップは無視する。
5. CORRECT question 5: 同じ成功反応の後、SET_COMPLETEへ。自動で次セットには行かない。
6. SET_COMPLETE: そのセットの5匹の画像を静止展示。小さい画面は「大きめ3匹+小さめ2匹」、タブレットは横5匹など。独立生成した画像をレイアウトで並べるだけで新規合成画像は不要。
7. SET_COMPLETEには子ども向けの2つの大カードだけ: 「もっと」=色つき動物+右矢印、「休憩」=静かな月+動物。**等しい視認性**で一方を光らせ続けない。自動遷移なし。絵の解釈は実際の子どもでテストする。
8. 「もっと」を選択: 次の5問の新セット、再び問1から。「休憩」を選択: REST。
9. REST: 動物1匹の静かな画面。目立つボタンは「遊ぶ」のみ。Androidの通常のホーム/戻る操作で離れられる。「遊ぶ」で新セット問1。
10. PARENT (将来): 子どもプレイとは別。現実に設定機能を作るまで歯車アイコン等を出さない。保護者には文字使用可、外部サイト/購入/広告検討は保護者確認後。

## D. 難易度とコンテンツ
| 問 | 目的 | 構成 | 1問の長さ（想定・制限なし） |
|---|---|---|---|
| 1 | とにかく理解 | 初回2択。まったく異なる影 | 10〜20秒 |
| 2 | 同じ操作を復習 | 異なる動物、位置はシャッフル | 10〜20秒 |
| 3 | 遊びのリズム | 異なる動物、同じ操作 | 10〜20秒 |
| 4 | 繰り返す楽しさ | 同じ難度、異なる動物 | 10〜20秒 |
| 5 | ひと区切り | 正答後に5匹展示 | 10〜20秒 |

- 最初の5問は全て2択、2→3→4択への移行は**セット境界**のみ。初期の累計5回/15回ルールは候補として維持し、試遊では直近5問の初回正答率/ヒント必要回数などで難度調整する。
- セット途中に選択肢数・候補位置を変化させない。1セット5問は異なるターゲット動物、シルエットの曖昧な候補は禁止。
- 小型画面の制約を最優先し、96dpの押下領域を確保できない場合は4択に上げない。
- 無操作時の指ガイドは**まず操作対象を教える**。最初から正解の場所を教えすぎない。2〜3秒無操作でカード全体を示すガイド、8〜10秒以降のヒント強化は試遊で判断（#16を更新）。
- 5問は設計の初期値。「3問・5問・8問」のどれが保護者と子どもに自然か実機試遊で評価し、決定したらコンテンツ設定で変更できるよう定数化する。MVPの初期設定は5。

## E. 途中離脱・再起動・休憩
### 端末に保存する最小状態
schemaVersion、setIndex、questionIndex(0〜4)、currentTargetId、optionIds（順番含む）、completedTargetIds（最新5個）、difficulty、phase(playing / celebrating / rest)、正解済みイベントID。**外部送信なし、氏名・生年月日・位置・顔写真等不要**。
- 誤答して閉じる: 同じ問/同じ並びで復元。
- 正解→演出中に閉じる: 正解を二重計上せず次の問へ安全復帰。5問目なら達成画面を復元。
- 達成画面で閉じる: 次回も達成画面、祝う動きは再生せず静止表示。
- 休憩画面で閉じる: 次回は新セット問1を自動表示（ホーム無し）。
- 値が壊れた/コンテンツIDが消えた: 安全に2択の新規セットへフォールバック。
- 途中復帰で勝手に広告・新ステージ・レベル選択・新しい答えの場所へ移らない。

## F. 広告の配置設計と採否
### まず採用する構成（MVP）
**全プレイ画面で広告0。広告SDK0。ゲームに広告用空白領域も取らない。** 一度に短く安心して遊べる体験で保護者の信頼を得る。自然検索のユーザー獲得を検証してから収益化判断。

| 候補位置 | 採否 | 理由 |
|---|---|---|
| アプリ起動直後 | **禁止** | Google Play Familiesの起動直後インタースティシャル禁止とUX |
| 単問ゲーム上/下のバナー | **不採用** | 誤タップ、選択カードの狭小化 |
| 正解/不正解/次問の直前 | **不採用** | 結果を阻害し突然の広告クリックを誘発 |
| 問5の達成画面 | **不採用** | ごほうび画面を広告で妨害しない |
| 「あと1問は広告を見る必要がある」 | **不採用** | 子どもに広告視聴を実質強要 |
| 休憩画面 | **不採用** | 休憩が広告の消化時間に見えるため |
| 将来の保護者画面の固定された1枠 | **要検証、MVPでは未実装** | 子どもから区別しやすいが、認定SDKやポリシー確認必須 |
| 保護者が明示的に選ぶ追加画像パックの買い切り | **将来の第一候補** | 追加コンテンツに対価、基本の遊びを無理に止めない |

### 将来、広告を導入する場合の必須チェック
1. [Google Play Families Policy](https://support.google.com/googleplay/android-developer/answer/9893335?hl=ja) の最新全文をチェック。子ども・年齢不明への広告は**Playファミリー向け自己認定広告SDKのみ**、個別化ターゲティングやリマーケティング不可、子ども向け内容・広告形式の要件あり。
2. 起動直後の全面広告、プレイを妨げ5秒後も閉じられないもの、1ページ複数広告、ゲームと区別できない内容、閉じようとして次広告が出る仕組みは禁止。
3. AdMob Flutterの場合は [Targeting公式文書](https://developers.google.com/admob/flutter/targeting) の**新しいageRestrictedTreatment**（古いtagForChildDirectedTreatmentは非推奨）と maxAdContentRating.g を最新SDKに合わせて確認。SDK自体の自己認定状態、対象年齢/地域別の法令も別途確認。
4. SDKは広告の表示以外にもデータ収集・権限・Play Console Data Safetyに影響。AD_ID、識別子、位置情報、プライバシーポリシー、同意等を監査。
5. 保護者エリアだけに置いても法令/プラットフォーム上の子ども向け配慮義務は消えない。広告のクリックが保護者ゲートを迂回して子どもを外へ連れ出すようにしてはいけない。
6. 子どもの正解数/プレイ時間に応じて広告を強制挿入しない。広告がない/読み込みに失敗した状態でも同じゲームが遊べる。
7. 保護者用領域は閲覧頻度が低いため**広告収益は小さい可能性**。子どもの遊びを犠牲にした収益増を狙わない。

## G. 離脱対策の設計意図
- 最初の正解までの操作を減らす。初回2択、触れたカードの即時反応（描画応答目標100ms以内）。
- 問1〜4は正解→自動次問でテンポを作り、1問ずつ続けるボタンは置かない。
- 5問だけで達成場面を見せる。達成後は静かに止まり、「もっと/休憩」を子ども自身が選ぶ。
- 休憩しても何も失わない。音や継続日数による強制報酬を設けない。
- 5匹の絵の展示は既存のMiniMax生成画像を並べるだけで成立。画像一貫性を要求しない。
- 長時間のプレイを誘引するデイリーストリーク、FOMO、勝手な動画再生、頻回の広告は作らない。
- **「途中で自然に終われる」ことも品質指標**とする。

## H. 自動テスト・試遊の受入基準
- [ ] 初回はスタートボタン無しで即2択。復帰は同じターゲットと影の並び。
- [ ] 問1〜4は1回の正解につき次問生成1回。問5のみ達成画面へ。
- [ ] 5問で5種類の動物が達成画面に表示され、同じ画像素材を使用。
- [ ] 達成画面は放置しても自動次問/広告へ進まない。
- [ ] 「もっと」と「休憩」が実際に機能。休憩から再開も可能。
- [ ] 無限タップ/多指接触/バックグラウンド復帰でも二重計上と状態破損がない。
- [ ] 最初の5問2択。難化はセット境界のみ。
- [ ] 360×640dpなどで両ボタンと動物が見切れず、スクロール無し。音無し、アニメ削減でも分かる。
- [ ] Kidsプレイ/達成/休憩に広告枠・広告SDK・強制課金無し。
- [ ] 試遊（保護者同意・同席、匿名）で3/5/8問構成、終了画面の2択の意味、最初の正答時間、完了時間、保護者の適正長を記録。
- [ ] 未解決の広告規約・安全問題があれば広告実装を見送る。少人数の試遊を効果実証と呼ばない。
