# Animal Shadow Match — ゲーム価値・発見・継続体験 v4.0

> 更新日 2026-10-14。ステータス **設計のみ、未実装**。
> 正本の優先順位: 本書は「遊びの価値/報酬/動物の反応/自由探索/新鮮さ」について v3 [セッションと広告](SESSION_AND_MONETIZATION_JA.md)と v2 [操作UI](UI_UX_SPEC_JA.md)を補完・上書きする。v3の5問1セット/続行と休憩/広告なし、v2の文字なし/大きなタップは維持。

## 0. 問題・仮説・差別化

現状の1問目〜5問目は「影を選ぶ→小さな成功→次へ」の繰り返し。幼児は操作を理解しやすいが、動物の種類が変わること以外に発見と意思決定の余地が少ない。大量の画像だけでは次回以降の面白さを保証できない。

**製品仮説**: 「ひとつ当てる→動物が違うリアクションをする→5匹と自由に遊ぶ」という短い因果関係と、自分がタップして起こす反応の選択が、単純な正誤判定よりも主体的な遊びになる。短時間で報酬を頻発させるより、**すぐ理解できる反応＋自由な実験＋自然な終了**を優先する。成長や集中力の改善は実証していないためストア宣伝で主張しない。

年齢による差が大きいため、2〜3歳/4〜5歳の探索的試遊で評価。短尺動画がすべての幼児の注意を損ねる、などと一般化しない。

## 1. 製品コンセプト — Shadow Friends

**「影を見つけて、動物と友達になる」**
- Primary loop (1問): 観察→影をタップ→選択した影がカラーの動物に→動物固有の控えめな動き→次問（1〜4問）。
- Set loop (5問): 5匹の動物が集合→自分で触って反応を試せる小さな遊び場→本人が「もう5問」「休憩」を選ぶ。
- Return loop: 次回は前回の途中から再開。多数の絵によって新しい動物が出会いとして登場。親に通知・連続ログイン・FOMOなし。
- **正解数そのものを報酬通貨にしない**。広告視聴、抽選、課金、連勝、レア確率、スタミナ、期間限定などは作らない。

## 2. 報酬の3階層（時間は初期仮説）

| 階層 | トリガー | 実体験 | 時間・制約 | 開発負荷 |
|---|---|---|---|---|
| A: 結果が伝わる | 毎問の正答 | 選択した影がカラー画像に変化、やさしく反応 | 目標100ms以内に視覚反応開始、200〜350msカラー化 | 小 |
| B: 生き物らしさ | 毎問の正答 | 動物の種類ごとに異なる控えめな動き（うさぎが跳ねる等） | 300〜550ms、数秒も見せ続けない | 小〜中 |
| C: 自分で遊べる | 5問クリア | 5匹が現れ、触れた動物だけが動く「おともだちパレード」 | 無操作時は静止、時間制限なし、自動次セットなし | 中 |

同じ動物の正解時リアクションは基本的に固定（学習しやすい）。**ランダムな特大演出や稀な宝箱を設けない**。音は後から任意で追加、音なしでも「反応した」ことが分かる。

## 3. 動物固有の微反応 — 1枚画像から実装

例（Flutterのtransform/tweenのみ、別姿勢画像不要）:
- うさぎ・カンガルー: 上へ8〜14dpジャンプ＋着地
- ゾウ・クマ: 左右±4〜6度スイング
- キリン・鹿: ゆっくり2〜4度傾く
- 魚・イルカ: 左右に6〜12dpスライド
- 蝶・鳥: 2〜3度回転＋小さく上下移動（過剰な羽ばたきアニメはしない）
- その他: 小さなスケール（1→1.06→1）

**使用するのは独立した単体PNG/WebP（透過）**。脚や目を個別アニメーションする必要はない。MiniMaxへのプロンプトも一匹の全身像だけにする。派手なflash・全画面紙吹雪・強い振動・警告音は避ける。

実装候補:
- Animal modelには reactionType (hop/sway/tilt/float/pulse) を任意で追加。未設定時pulse。
- ReactionsはUIから独立した animation preset を持ち、途中disposeやreduce motionへの対応をテスト。
- ランダム「レア」反応は禁止。動物ごとの動作を観察して子どもが予測できる方を優先。
- 正解時のクロスフェードは silhouette WebP→original WebP へ1回だけ。反応中は選択肢の入力をロック。正答から次問まで約1.1〜1.5秒を目安とし、試遊で短縮/延長を決める。

## 4. 5匹で遊ぶ画面 — Interactable Parade（中心機能）

- v3の5問完了画面に、直近に正解した**5匹の採用済み独立画像**を配置する。背景は単色〜簡素な地面や雲をコードで描画。
- 各画像は最小96dp以上のタップ対象をできるだけ維持。実際の画像そのものは画面サイズに合わせて可変。重なる場合もタップ領域が混線しないよう明確に分ける。
- 子どもが1匹をタップしたら**その1匹だけ**300〜550ms動く。複数動物の一斉自動再生は禁止。多指連打/重複入力時は同一動物をデバウンス。
- 触れた動物の輪郭を僅かに持ち上げ、どれを触ったか即座に見せる。音なし、文字なしで成立。
- 観察と自由遊びに点数、ミッション、失敗、時間制限は設けない。
- 達成画面には **「さらに5問」「休憩」** を示す絵ボタンを従来通り2つ残す。両者同等の視認性。動物を触る行為で誤って次セットに進まない。
- 休憩に入ればいつでも離れられる。おともだちとの長時間の遊びを無理に引き延ばさない。
- **重要:** 画面の狭い端末で5匹全てを押せるのが難しければ、パレード画像を大きくすると同時に「左/右の静止ページ送り（1回タップ）」方式を比較。タップ96dp未満の小さな5匹を無理に押させない。
- 背景用画像を新たに生成するのは必須にしない。MiniMax画像の合成編集・一貫した複数姿勢を要求しない。

## 5. 繰り返し遊ぶ理由：画像数×出題の幅×小さな新発見

### MVP（必須）
- 初回5問は輪郭が明確に異なる動物。1セット内でターゲットの重複ゼロ、直近2セットの重複を可能な範囲で抑える（十分な動物の数がある場合のみ）。
- まず20匹程度の品質重視で試作→100〜200匹まで徐々に拡充。ただし単純な量よりシルエットの違いと出来の良さが重要。
- 動物ごとのreactionTypeと、シルエットの違いが分かりやすいタグ（long_neck, big_ears, wings等）をデータに付与できるようにする。
- あまりにも似ている動物ペアを避け、最初に誤答した原因が「影の区別が不可能」でないか確認。

### P1（価値が検証された後）
- セット完了時の「ミニ生息地」を追加。森林、海、草原などに応じて**コード背景（グラデーション/形）**を差し替える。動物との位置/サイズを合わせるだけでMiniMaxの複雑な背景合成は不要。
- 子どもが同じカテゴリに飽きないよう、次セットのテーマをゆるく変える。最初の起動にカテゴリー選択画面は追加しない。
- **ふれあい図鑑**を保護者設定または達成後の任意導線で試す。採用済み動物画像を並べ、触ると同じ微反応。コレクションの未獲得数/％、鍵マーク、強い煽り、課金誘導は禁止。

### P2（4〜5歳のみ、試遊の後）
- 追加画像を用意せず、**リバース影合わせ**を保護者が任意選択：上が影、下がカラー動物2〜4択。初回の幼児へ自動的に混ぜない。遊び方が突然反転すると混乱する可能性を検証する。
- 2歳児用にモードが増えすぎないよう、1画面即プレイを堅持。

## 6. 子どもの注意を守る制約（v3から継続）

1. スクロール動画や連続自動再生ではない。子どものタップが原因で反応すること。
2. 5問ごとに自然な区切りがあり、そのまま終われること。強制「あと一回」/時間限定アイテム/ログイン連続記録なし。
3. 不正解を嫌な出来事にしない。困っている場合は静かなヒントで支援。
4. 過度な画面点滅・大音量・隠された広告・「一番レアな動物」抽選無し。
5. 広告はMVPにゼロ。今後保護者の操作から検討する場合も[Families Policy](https://support.google.com/googleplay/android-developer/answer/9893335)を独立レビュー (#23)。
6. 報酬は「操作が世界に与える変化」であって、プレイ継続を強要するポイントや確率ではない。

## 7. 実装単位と責務

- Dart Animal: reactionType（追加フィールドは後方互換でdefault）。
- Domain: SessionControllerはセット5問と次問/完了/休憩を保持（#20, #22）。Reward演出を正解数でコントロールしない。
- UI: AnimalReactionWidget（#24）、InteractableParade（#25）を小コンポーネントとして分離。Android低速端末でなめらかに動くこと。
- Data: 画像は assets/animals/ と JSON、背景は原則Flutter CustomPaint/DecoratedBox。追加する場合にも独立画像のみ。
- Tests: 動物ごとのアニメ種別/未定義fallback、1問の反応1回、5問で5画像一致、連打/画面復帰、reduce-motion、セマンティクス、低メモリ/画像欠損。広告関連依存なし。

## 9. 実証計画：それは本当に楽しいか

保護者同意と同席で探索的に試す。大人が正解を教えず、途中で止めたい子には終了を尊重する。個人識別子、顔動画/位置を収集しない。**MVPの合格値は仮説、統計的有意性ではない。**

### 比較対象（順次・条件を揃える）
- A（ベースライン）: 現行の影→単純な成功→5問完了。
- B（最小改善）: 動物固有の小さな反応。
- C（優先採用案）: B + 5匹のおともだちパレードで任意タップ。

一度に全変更を投入せず「追加した遊びによって何が良くなったか」を観察できるようにする。A/B/Cを子どもに機械的にランダム配信する遠隔実験はしない。研究的検証はローカル・保護者同意。

### 観察指標
- **理解:** 初回3問中の一度以上の自力正解、必要だった大人の補助の回数。
- **発見:** 動物の反応を視線で追ったか、説明なしにパレードの動物を自発的にタップしたか。
- **自律:** 達成画面で「もっと/休憩」を迷わず使えたか、休憩時に混乱しないか。
- **繰り返しの質:** 自分から別の動物を選ぶ/再タップする、翌日再利用したいか（保護者の任意評価）。離れたいときに離れられたか。
- **負の反応:** 反応待ちで苛立つ、同じ動物ばかり選ぶ、アニメが怖い/うるさい/落ち着かない、誤タップ、画面の情報過多。
- **性能:** タップから初回反応 <100msは目標であって端末実測が必要。60fps目安、低性能端末・reduce-motionで破綻しない。
- **価値仮説の優先順位:** まず主体的タップ/理解/保護者信頼、次に自主的継続。プレイ時間が延びたこと単独を成功とみなさない。

### 受入基準（実装）
- [ ] 画像の追加作業は「単体絵 + metadata」で済み、複数の一貫した画像生成を要求しない
- [ ] 1回の正解に対して反応は1回、動物別presetは一貫、アニメにタップを奪われない
- [ ] 5問目で5匹を並べ、動物を個別タップすると個別に軽く動く
- [ ] さらに5問/休憩の明瞭な2択、誤タップで意図しない遷移無し
- [ ] 2〜3歳、4〜5歳の双方で説明なしの試遊結果を記録
- [ ] Android小画面・大型画面・無音・減らしたアニメ・スクリーンリーダーに対応
- [ ] 正解で罰・動画・広告・希少性煽り・課金誘導が発生しない

## 10. 優先度とスコープを増やし過ぎないための境界

| 機能 | 優先度 | 理由 |
|---|---|---|
| 動物ごとの小さな反応 | **P0** | 既存画像のままで単純正誤を遊びへ改善 |
| 5匹のタップできるパレード | **P0** | 5問で終わるだけでなく本人の探索に変える |
| 大量画像の輪郭品質・出題の新鮮さ | **P0** | 同じ問題の飽きと不公平感を減らす |
| 生息地の静かなコード背景 | P1 | 選択肢を増やさず見た目の変化を作る |
| ふれあい図鑑 | P1/検証後 | 自由探索を広げるが、追加ナビゲーションが必要 |
| リバース影合わせ | P2/4〜5歳向け検証後 | 画像再利用可能だが操作ルールが変わる |
| コイン/限定レア/連続ログイン/広告でアンロック | **不採用** | 遊び自体の価値より継続圧力に依存 |

**最初に作るのは「動物別反応」と「触れる5匹」だけ**。画像・UIが増える付帯機能は、実機試遊で足りないと判明するまで増やさない。
