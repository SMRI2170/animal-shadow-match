## 2. 比較する3テーマ

| テーマ | オリジナル性 | 親が分かるか | 幼児が輪郭を合わせられるか | MiniMaxによる独立量産 |
|---|---|---|---|---|
| A 動物（ベースライン） | 弱い | 非常に強い | 比較的理解しやすい | とても容易 |
| B **ふしぎなともだち / ソフト3Dのオリジナルキャラ** | 強い | スクリーンショットで明示必要 | 形の設計と選定に依存 | 容易（別ポーズ不要） |
| C ふしぎなおもちゃ・魔法の道具 | 中〜強 | 絵の内容次第 | 物により差が出る | 容易 |

**現時点の第一候補: B。** やさしい色・怖くない表情のオリジナルの「ふしぎなともだち」を生成し、シルエットを当てると実体化、5匹揃うと触って遊べる。動物では得にくい世界観/IPの独自性を作る。Cは安全な比較候補。Aは比較用の現行体験で残す。

### Bのゲーム体験（v3/v4を壊さない）
1. 起動直後: ソフト3Dの単独オリジナルキャラ1体が表示され、下に異なる輪郭2つが出る。
2. 正解: 対応する影がカラーになり、キャラがちょっと跳ねる/揺れる。**同じ透過画像を使用**。
3. 1〜4問: 次のふしぎキャラへ自動進行。
4. 5問目: 出会った5体が「おともだちパレード」に並ぶ。好きなキャラをタップすると個別に動く。
5. 「もう5問」「休憩」の等しい大きさの選択ボタン。広告、タイマー、スコア、レア抽選/課金誘導なし。
6. 最初からカテゴリー選択をさせない。キャラ名を読ませない。ストア説明だけ検索語をローカライズ。

## 3. 画像のデザイン契約

- 画像1枚につき**キャラクター1体**（複数キャラ禁止）、前面寄り、全身、パステル/ソフト3Dの粘土おもちゃ風、怖い牙やホラー風の表情無し。
- 輪郭に差をつける: 角の個数、アンテナ、耳、体形（丸/三角/縦長/星型に近いが角が丸い）、腕の本数、尾、突起。ただし2〜3歳向けに細すぎる線は不採用。
- 独立したMiniMax生成でよい。キャラの別ポーズ・集団の合成生成・プロンプトによる完全同一顔の再生成を要求しない。
- 背景除去後の透過画像からアルファマスクにより**輪郭一致の影を自動生成**。輪郭が壊れる画像は不採用。
- 画像と同じ背景色のため輪郭が薄くなること、伸びすぎた突起・怖い顔・著名キャラクターを想起させる外見・似た輪郭が続くことはNG。
- 最初は**Bを20枚、Cを12枚**試作して、Aの現行動物とUIを揃えて比較。大量本番生成は合否判定後。
- 色・形・大きさ・描画スタイルを揃えるため、共通の短い画風指定と各画像のシルエット特徴（例: antennae=2, body=wide）だけを指定する。複雑な合成プロンプトは使わない。

### 最小メタデータ例

```json
{
  "id": "friend_001",
  "type": "fantasy_friend",
  "image": "assets/friends/friend_001.webp",
  "shadow": "assets/friends/friend_001_shadow.webp",
  "silhouetteFeatures": ["two_antennae", "wide_body"],
  "reactionType": "hop",
  "approved": false
}
```

キャラ一覧が採用された場合、既存 `Animal`, `animal.id`, `animals.json` を順次 `ShadowItem`, `item.id`, `items.json` などへリファクタリングする**別Issue**を起こす。既存の作品を全削除・名称の全置換を先走らない。

## 4. 検証方法と判断基準

### 第1ゲート: 素材品質（B 20枚、C 12枚）
- 96〜120dpの実サイズでもシルエットが識別できるか。
- 20画像の輪郭が似すぎないか。最低15枚を「明確な異なる輪郭」として採用できるか（初期の開発目標）。
- 画像の表情は怖くないか、色/質感が概ね一貫しているか。
- 画像生成から透明化・影生成・採用までの作業時間と失敗率を測る。

### 第2ゲート: 子どもと保護者の試遊（#19）
- 2〜3歳、4〜5歳、保護者の同意と同席のもとA/B/Cテーマで見た目だけを変え、操作方法は同じにする。
- 最初の3問で正しい影を選べるか、どういう意味か理解したか。
- 自発的にタップするか、5匹パレードを触りたくなるか、怖い・混乱する表情がないか。
- 画面への興味だけでなく、保護者がGoogle Playの検索画面で何のゲームか**即理解するか**。個人情報を不要に取得しない。
- 3〜5名ずつ等の少人数の比較は探索的。統計的優位や将来の獲得率を保証しない。
- BがAより初見の理解を大きく悪化させず、意欲的に触りたがるならBへ正式移行。Cがより評価されればCを採用。判断値は試遊前に決めて結果を記録。

### 第3ゲート: ASO（#13、#15）
- 検索語候補: `shadow matching for kids`, `shadow puzzle toddler`, `shape matching for toddlers` を実測・現地化。**検索語としての需要は未確認**。
- 仮のストア名候補: `Mochi Shadows: Kids Puzzle`（仮称、商標・既存アプリ/ドメイン重複未精査）。直接競合する `Monster Shadow Match` は避ける。日本語仮称「ふしぎなかげあわせ」。
- タイトルはGoogle Playの30文字上限と関連性要件を確認し、機能（影合わせ）が一目で分かるスクリーンショットを作る。ブランド名だけでは検索獲得を保証できない。
- 本番公開30〜60日後にPlay Consoleの検索語句・ストア訪問・インストールを評価する。
