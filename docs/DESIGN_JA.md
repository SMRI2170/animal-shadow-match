## 研究開発上の仮説

「幼児の影合わせ」という限定された検索意図を狙えば、広い「ジグソー」市場より、個人開発が自然検索からインストールを得やすい可能性がある。ただし、この仮説は検索ボリュームや競合の現在の検索順位により検証する必要があり、ブルーオーシャンと断定しない。

- **利用者**：2〜5歳児（ストア検索・インストールの意思決定者は保護者）
- **価値**：文字や母語に依存せず、動物を見て正しい影を1回タップするだけで遊べる。
- **差別化の方向**：柔らかいソフト3D風の動物を大量に採用、短い成功演出、わかりやすい2→3→4択への段階化。
- **開発制約**：1人で実装可能、サーバー不要、AI画像の複雑な編集・組み合わせ不要、オフラインで完結。

## UI/UXの正式仕様（v2.0、実装前）

**[UI/UX詳細設計](UI_UX_SPEC_JA.md) を画面・操作・フィードバックの実装時の優先仕様とする。** 本文の旧仕様と競合する場合は UI_UX_SPEC_JA.md を優先する。

- アプリ起動後、タイトル画面やスタートボタンなしで2択のゲームを表示する。
- 星5つの進捗バーを非表示にし、画面内の目立つ情報は「動物1匹 + 影2〜4択」に絞る。
- 初回/無操作時は指のアニメーションで無言の操作ガイド。誤答で減点や音は出さない。
- 正答は選択影を同じ位置でカラー化し控えめにバウンス。アニメーション中の連打を無視。
- 360×640dpでスクロールなし・大きな選択カード。保護者向け入口は後付け可能な別導線。
- 初期設計の「正答後0.85秒で次問」は廃止し、視認性を見ながら約1.1〜1.5秒で遷移する設計仮説に変更。
- 既存コードはプロトタイプのため未対応。実装と試遊の完了をもって公開候補とする。

## ゲーム体験の仕様（初期プロトタイプの記述、詳細はv2.0を優先）

1. 画面上方にカラー動物1匹を見せる。
2. 下方に黒いシルエットを2個、のちに3個・4個提示する。
3. 子どもは同じ輪郭を1回タップして答える。
4. 正答なら短いキラキラ／弾む演出を表示し、約0.85秒後に次の問題に進む。
5. 誤答なら軽い色変化だけを返し、正解するまで続けられる。

画面内の説明文、スコア、ライフ、制限時間、ログインボタン、広告枠はMVPに含めない。初回の理解度が不十分であれば、1回だけ表示する手のジェスチャーアニメーションを追加する（実装前の試遊で判断）。

## デザインシステム

- 背景：クリーム色 `#FFF9F0`。影：濃い青みグレー `#253134`。
- 主なカラー動物：ソフト3Dのクレイ玩具風。1匹だけ、全身、丸い形、目は優しい表情、低刺激のパステル色。
- 影の候補：角丸白カード。正答時は淡い緑、誤答時は淡いオレンジ。
- 端末：Androidスマートフォン縦向きを第一ターゲット。360dp幅の実機を含めて確認。
- 音声：MVPでは未実装。無音でも成立することを保証し、その後、音のON/OFFを保護者向けに実装する。

## MiniMax生成素材の使い方

**AIには単一の完成絵を生成させるだけ。影はコードで自動作成する。**

生成された絵は、必ず透過PNGに背景除去し、動物の輪郭に欠けがないか検査する。`scripts/prepare_assets.py` で同じアルファマスクから色つきWebPと黒い影WebPを生成するため、生成AIが影を別画像で再現する必要はない。例：`giraffe.webp` → `giraffe_shadow.webp`。 

大量生成より優先するのは影の区別のしやすさ。見た目がかわいくても、耳・尾・脚が隠れて影が他の動物に似てしまったものは不採用とする。採用画像の大きさが増えたらカテゴリと紛らわしい候補を手動で整理する。

## 技術構成

```text
Flutter
  ├─ UI: lib/ui/game_page.dart
  ├─ 問題生成: lib/domain/round_factory.dart
  ├─ データ型: lib/domain/animal.dart
  └─ アセットJSON読込: lib/data/catalog_repository.dart
画像ソース（開発環境のみ）
  └─ MiniMax → 背景除去 → 画像整形 → 影生成 → QA
アプリ本体
  └─ JSON + WebPを同梱。クラウド通信なし。
```

外部Flutterパッケージは最小限とする。将来的に状態保存・音声などを追加する際も、必須の目的を先に定義したIssue単位で導入する。
